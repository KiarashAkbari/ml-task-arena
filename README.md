# Stage 1 — Data Factory

Reproducible dataset factory for NYC 311 service requests (Term 3, Stage 1).
Challenge sources live in `files-given/`; the working contract for assistants is `AGENTS.md`.

## How to run

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
pip install -e .

python -m unittest discover   # tests, offline
data-factory                  # whole pipeline (resumable; stages append over time)
data-factory fetch            # only the fetch stage
data-factory curate           # contract gate: quarantine + per-reason counts + threshold
data-factory clean            # cleaning + population join -> data/curated/cases.csv
data-factory outputs          # aggregate + data-quality report + run_manifest.json (hashes)
data-factory --show-config    # resolve and print the active configuration

data-factory fetch --since-last-run   # moving window: only "since the last run" (§4.8.1)
data-factory run --since-last-run     # same window, then the whole pipeline
```

One command runs the whole factory (`run`, the default); a parameter runs a
single stage. `--since-last-run` changes *what* is fetched, not which stage
runs, and is accepted only by `run` / `fetch` (anything else exits 2).

After a full run, open `solution.ipynb` and **Restart Kernel & Run All**: it
narrates the delivered dataset (provenance, generated data-quality report,
duration/outlier analysis, per-capita rates, seven claim-backed charts) and
writes nothing. All analysis logic lives in `src/data_factory/eda.py` and is
covered by `tests/test_eda.py`.

The fetch stage pages the locked scope into `data/raw/` one batch at a time
(`fetch_checkpoint.json` records progress), so Ctrl-C anywhere and re-running
continues where it stopped; re-running a completed fetch makes no HTTP requests.

**Source shape guard (AGENTS §4.8.2).** A page's key set is *not* a schema:
Socrata omits a field when every value in that page is null (a live run met
`vehicle_type` for the first time at page 36). So the guard has two layers:
once per invocation the dataset's declared schema is read from
`/api/views/<id>.json` — a mapped field that is no longer declared, or a
declared type that differs from the one stored in the checkpoint, stops the
run with exit 5; per page, a mapped field that turns into an object/array also
stops it. Columns that merely *appear* mid-run are recorded in the checkpoint
and reported (`source schema: column(s) first seen mid-run: …`), never treated
as errors. If the metadata endpoint is unreachable the audit degrades to a
recorded warning instead of breaking a resumable fetch, and
`run_manifest.json` reports the outcome under `fetch.schema_audit`.
The curate stage never drops data silently: contract violations go to
`data/curated/quarantine.jsonl` with reason codes, counts are printed every
run, and a quarantine ratio above `quarantine.max_ratio` fails the run (exit 5).
The outputs stage writes `cases.csv`, `aggregate.csv`, the generated
`data_quality.csv`, and `run_manifest.json`, which hashes all of them.

## Moving window — `--since-last-run` (AGENTS.md §4.8.1)

Instead of always re-fetching the configured `date_range`, one parameter
fetches only what is new: `[previous window end + 1 day … today]` (UTC).

* The previous window comes from the fetch checkpoint (`window_start` /
  `window_end`), or from the last `run_manifest.json` when the raw directory is
  gone. The window is recorded in the checkpoint and reported in the manifest
  as `window: {start, end, mode}`, where `mode` is `configured` or
  `since_last_run` — the manifest can never claim a window the data lacks.
* The previous raw window is **renamed, never deleted**:
  `data/raw/` → `data/raw_archived/<start>__<end>/`, together with a copy of
  the manifest that described it; `archive name already taken` is a loud error
  (exit 5), and existing archives are listed in the manifest as
  `archived_windows`.
* If the last run already ends today there is nothing new: the factory
  re-runs the previous window, makes **zero** HTTP requests, and re-emits
  byte-identical outputs (idempotency, §4.2) instead of failing or querying an
  empty range.
* No previous run at all → loud error (exit 5) telling you to run once without
  the flag; a window is never invented.
* Checkpoints written before this feature (without the window keys) are
  refused with the same clear remedy: remove `data/raw/` and re-run.

## Data-quality report — `data_quality.csv` (AGENTS.md §4.8.4)

Generated by the `outputs` stage from the delivered dataset, never written by
hand: one row per column of `cases.csv` with `empty_count` / `empty_pct`,
`unique_count`, the observed range (`min` / `max`: numeric for integer
columns, chronological for dates, lexicographic for text) and, for every
non-identifier column, the three most frequent values with counts. The
file is hashed in `run_manifest.json` like every other output, so the numbers
quoted in the report or notebook trace back to the exact dataset.

## Population reference source (required before `clean`)

Choose a public ZIP → population table (NYC Open Data or Census; finding and
validating it is part of the challenge), normalize its header to

```csv
zip,population,borough
10001,25000,Manhattan
```

(all three columns required — `borough` feeds both the section 3 district
cross-check and the population rates of the aggregate table; county names like
`Kings` are normalized automatically),
save it as `data/reference/zip_population.csv`, commit it (it is small
reference data, not raw 311 dumps), and record its URL + fetch date in
`config/default.json` under `population.source_url` / `population.fetched_date`
for the report and manifest.

`scripts/build_population_reference.py` builds exactly that file from two
sources independent of the 311 data — the population table, and the NYC
ZIP-plan rule for the district — then validates the result through the same
loader `clean` uses:

```bash
python scripts/build_population_reference.py --write-config
python scripts/build_population_reference.py --check      # re-validate anytime
python scripts/build_population_reference.py --csv PATH   # offline/blocked network
python scripts/build_population_reference.py --url URL    # any published CSV/JSON
```

It tries the Census API first (2020 DHC P1 by ZCTA, the full national table).
If that host is unreachable — a real run got a read timeout followed by HTML
instead of JSON — it falls back to **NYC Open Data's Modified ZCTAs**
(`data.cityofnewyork.us/resource/pri4-ifjk`), which publishes a population
estimate per MODZCTA plus the ZIPs it covers, on the same host as the 311
source. A MODZCTA bundling several ZIPs has its population split across them
so the per-borough denominators are never double-counted; that split is the
one approximation in the file and is reported by the script. Whichever source
wins is recorded verbatim in `population.source_url`, so the manifest and the
report always name the source that was actually used.

The 110xx prefix is deliberately excluded (it mixes Queens border ZIPs with
Nassau County), so a handful of cases keep a null population and show up in
`clean`'s `zip unknown` count instead of quietly inflating a borough's
denominator. `fetch` and `curate` do not need this file — only `clean` and
`outputs` do.

## Source field map

`source.field_map` in config binds canonical field names to the raw API field
names (e.g. `zip_code → incident_zip`). Confirm them with one request before
the first live run:

```bash
curl -sS 'https://data.cityofnewyork.us/resource/erm2-nwe9.json?$limit=1'
```

If a raw name differs, fix it in config — no code changes (AGENTS.md §1).

## Determinism check (AGENTS.md §4.5)

Two independent runs on the same window must list **identical `outputs`
hashes** in `run_manifest.json` — `cases.csv`, `aggregate.csv`,
`quarantine.jsonl`, `data_quality.csv` (the manifest's own `started_at` /
`finished_at` are metadata and differ by design):

```bash
data-factory run && cp data/curated/run_manifest.json /tmp/run1.json
data-factory run   # fetch is a no-op; curate/clean/outputs re-emit identical bytes
python - <<'EOF'
import json, sys
a = json.load(open('/tmp/run1.json'))['outputs']
b = json.load(open('data/curated/run_manifest.json'))['outputs']
print('MATCH' if a == b else f'MISMATCH\n{a}\n{b}')
sys.exit(0 if a == b else 1)
EOF
```

## Configuration

All tunables live outside the code in `config/default.json` (source URL, locked
scope — agency + explicit complaint types —, date range, batch size,
paths, retry cap, backoff/timeout, quarantine threshold). Point to another file
with `--config PATH`. Unknown keys are rejected so typos fail fast.

`paths.raw_archive_dir` (default `data/raw_archived`, derived from the raw
directory name when omitted) is where `--since-last-run` renames rolled-over
raw windows; it must not overlap `paths.raw_dir`.

## Notebook (`solution.ipynb`)

The notebook is a *narration* layer, not a second implementation: every number
it prints comes from `data_factory.eda` (tested offline), it reads only the
published artifacts (`data/curated/cases.csv` and friends), and it verifies
the dataset's sha256 against `run_manifest.json` before analysing it.

Paths are relative to the project root, the seed is fixed once (`SEED`), and
two runs print identical numbers. Run it with **Restart Kernel and Run All**
and save the outputs — an unexecuted notebook is not accepted (AGENTS §5.2/5.3).

## Exit codes

| code | meaning |
|------|---------|
| 0 | success |
| 1 | unspecified failure / unexpected bug |
| 2 | command-line usage error (argparse) |
| 3 | configuration error |
| 4 | network / HTTP error |
| 5 | data validation error |
| 130 | interrupted (SIGINT) |

Exact dependency pins live in `requirements.txt` (kept in sync with `pyproject.toml`).
Data directories (`data/raw/`, `data/curated/`, `data/raw_archived/`) are created by the pipeline itself and are never committed.
